# Mini-EP 课程首页

当一个 Token 选中的 Expert 位于另一张 GPU 上时，输入先送到那张卡，计算结果再送回来。十二课沿这次往返展开：前六课建立单设备 Reference 与真实 NCCL Expert Parallel；

第七、八课学习扩展、负载与测量；第九至十一课分别处理稳定打包、融合合并与分组矩阵乘；第十二课用 Peer 映射显存和设备侧信号连接通信与计算。每个优化实现都回到同一份路由记录、布局关系和数学输出上。

课程面向具备 Python、PyTorch 与基本矩阵运算知识的读者。第一、二课的 Reference 和布局推导支持 CPU；第三课的设备计时使用一张 CUDA GPU；

第四至八课的 NCCL 示例使用 1～4 张 NVIDIA GPU；第九至十一课增加 Triton。第十二课使用单机 Peer 访问、跨 GPU 原子操作、PyTorch symmetric memory 与 Triton TensorDescriptor，TMA 路径要求计算能力至少为 9.0。

各课在实现和示例附近说明 dtype、布局及运行配置。

## 贯穿课程的数据流

Router 为每个 Token 选出 K 个 Expert，并给出分支权重。Dispatch 展开路由记录，按 Expert 与目标 Rank 整理输入；正向 All-to-All 将向量送到参数所在地。

本地 MLP 计算后，结果写回接收位置，再由返回 All-to-All 送到输入来源。源端恢复排列并加权，输出重新按原 Token 行排列。Token 编号、slot 与权重在逻辑上始终配对；

基础 EP 的恢复索引与权重保存在源端，目标端使用计数和块内顺序确定 Expert 归属。

第一课用两个 Token 建立分组和加权，第二课增加第三个 Token 与空 Expert，固定六条记录及其逆排列；第五课将同样六条记录送过两张 GPU。第六课扩展到真实 MLP 和八个 Token，第七、八课增加 GPU 数与受控热点。

第九至十一课沿已明确的布局逐段实现 Kernel，第十二课再为远端写入建立可读时刻与复用边界。完整实现保留在大代码块中，重要分段在相邻的小代码块中解释输入、地址、边界与结果。

### 统一符号与布局语言

单设备阶段的 T 表示整批输入行数。进入 EP 后，T 表示全组原始 Token 数，N 表示本 Rank 的输入行数；等分示例满足 N=T/P。原始 Token 与展开记录分别计数，吞吐使用前者，Expert 负载与通信行数使用后者。

| 符号或名称 | 含义 |
| --- | --- |
| H、F | 隐藏宽度与 Expert 中间宽度 |
| E、K、P | 全组 Expert 数、每 Token 的 Top-K 分支数、EP group 大小 |
| L=E/P | 均匀放置下每 Rank 的 Expert 数；第十二课源码记为 Q |
| 全组 TK、本来源 NK | 展开后的路由记录数；前两课用 A=TK，第九课源码用 S=NK |
| Expert-major | 先按 Expert 分组，组内保留稳定的原记录顺序 |
| Rank-packed | 发送端先按目标 Rank 分块，接收端先按来源 Rank 拼接 |
| pack_index、restore_index | 打包行到原记录、原记录到打包行的两个查询方向 |
| send_splits、recv_splits | 长度为 P、以第 0 维行数计量的目标块长与来源块长 |

矩阵乘公式中的 K_gemm 表示归约宽度，Up 为 H，Down 为 F；代码或基准参数中的 GEMM K 采用同一含义。第十二课的固定容量 C=NK 与目标容量 M 分别决定源端分段和目标端 Expert 行地址，实际有效行数单独由 counts、rows 描述。
