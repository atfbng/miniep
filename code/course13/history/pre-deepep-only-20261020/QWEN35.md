# Qwen3.5-35B-A3B 接入与验证

本扩展只接管 Routed Experts，沿用 Router → Rank packing → A2A → Grouped SwiGLU → Return A2A → Combine。Shared Expert 的 MLP/gate、混合 Attention、循环状态、缓存与采样由 vLLM 提供。

## 已验证范围

模型为本地 Qwen3.5-35B-A3B BF16 权重，40 层、H=2048、路由 Expert F=512、256 Experts、Top-8，加一个 F=512 的 Shared Expert。实测环境为 H100 80GB、vLLM 0.29.0、PyTorch 2.13.0+cu130、Triton 3.7.1、Transformers 5.16.1；Attention TP=2、DP=1/2、MoE EP=2/4，eager、同步调度、文本输入。其他同架构尺寸、图像、量化和 MTP 未作为本次支持结论。

| 验证 | 范围 | 结果 |
|---|---|---|
| 原生 smoke | 两条请求各32 Token，独立重复调用 | Token 序列完全相同 |
| 完整双卡语料 | 32 prompts × batch1/2/4/8 ×64 Token | 128/128 序列一致 |
| 双卡长生成 | 4 prompts × batch1/2 ×128 Token | 8/8 序列一致 |
| 完整四卡语料 | 9类工作负载，含空DP、不等长请求、2040 Token输入 | 22/22 序列、314/314 Token一致 |
| 完整逐层与同前缀Logits | 每Rank40层；分别建立原生基线 | 最大绝对误差均为0 |
| 最终双卡逐层复验 | 两Rank各40层、640次调用 | 最大误差0 |
| 精简后四卡复验 | 同9类场景，每Rank5480次层调用 | 40层全覆盖，最大误差0 |
| 精简后Qwen3回归 | 两Rank各48层、768次调用 | 最大误差0 |
| 精简后单元与核心NCCL | H100执行28项；EP1/2/4各48个核心案例/Rank | 全通过；GPU套件无skip |

完整语料先在精简前版本验收，最终精简版再次做上表逐层回归，两次候选性能对照中的生成Token也全部一致，但性能门槛未通过，候选均已撤回。最终热路径指令与完整验证基线一致；不通过放宽误差阈值或删除慢样本保留精简。

初次四卡汇总发现环境文件漏写模型层数，报告因此按旧模型48层判失败。各阶段输出记录已保存一致的模型族和40层信息；修复记录位置后，从全部16份原始阶段/Rank记录恢复环境信息并重新执行原有严格报告。原始失败报告、环境文件和恢复说明均保留，模型输出和数值门槛未修改。

## 与前课一致的部分

主流程使用前课熟悉的 `restore_index` 局部名称，含义仍是“原始 Token/slot 应读取哪一返回行”。既有结构接口保持不变：变长布局为 `packed.restore_index`，固定布局为 `fixed_packed.combine_index`；固定有效行数为 `valid_rows`，容量另由 `rows_per_rank` 表示。TEACHING.md 明确给出对应关系以及地址组合，避免把不同缓冲区的行号混用。

两次更积极的热路径精简均未通过四卡 Prefill 的预设性能门槛，已全部回退。最终保留完整验收基线的推理函数和方法：实际 Python 3.12 核对了字节码、常量、调用名、异常表和局部槽位；除一个不改变槽位的局部变量改名，其余一致。另18个核心文件逐字节一致。

最终整理只收敛初始化中的不安全覆盖配置，并合并外围验证日志的重复代码。默认推理属性与对象布局保持原样；`MINIEP_OWNER_PARTIALS=0` 不再允许，独立 Reference 与历史数值实验保留。日志区分 DP 策略与 Shared Expert 所需的实际 owner 部分和。没有为了缩短代码修改 Kernel、GEMM、通信顺序或舍入位置。

## Shared Expert 的必要边界

双卡无SP时，Shared Expert权重按TP分片。每Rank先做BF16的 `shared_partial + routed_owner_partial`，再调用原生TP归约。先分别归约两条分支再相加会改变舍入，不能为了缩短代码而交换顺序。

四卡SP时，Shared Expert为本Rank的Token行保存完整权重；路由结果按原生owner顺序归约后，再与本地共享分支相加。所有这些处理都集中在 `mini_ep/integration`，核心EP不依赖循环状态或Shared Expert。

## 复现

从本课目录运行，使用新的输出目录，完整命令见 README 的双卡/四卡验证入口。验证报告从checkpoint记录实际层数；Qwen3为48层，Qwen3.5为40层。原生、Teacher-forcing和自由生成必须使用同一权重、输入及配置，不混用两个模型的Logits基线。

精简前后的性能对照单独记录，不能把这里的Qwen3.5结果与先前Qwen3-30B-A3B的绝对延迟直接比较。本轮没有优化Attention/循环状态，也没有宣称新增通信计算重叠。
